到底为什么出错 · 四环因果链

  1. 数据是「漏的」，不是满的

    每个患者有一批肽（行），但不是每个工具对每条肽都有分数 —— 肽长超范围 / HLA 不匹配就填 NaN。 HLAthena 在 P101 的 12 行里 只有 3 行真有分数。「12 行」≠「12 个分数」，这是坑的地基。

  2. 3 个点算相关，必然凑出 ±1（数学必然）

    3 个点算秩相关，只要碰巧单调就是 ±1，约各 1/6 概率撞完美 ±1。稀疏覆盖的工具必然刷出假的 ±1。 实测：全部 13 个 rho=±1 的格子，无一例外落在有效点数 effN=2 或 3 的患者上（重灾 = P102）。

  3. 门槛数错了分母 真 BUG

    代码本有防线 FISHER_MIN_N=3（点数 ≤3 就剔），本意正是挡这种伪相关。但门槛判定用的 n=len(g) 是患者总行数（8–19，全 >3），不是工具有效点数 effN。 于是 2-3 点凑的 ±1 顺利过门槛、满权进入聚合。

  4. clip + arctanh 把假分放大成「重炮」

    rho=1 会让 arctanh 爆掉，所以 clip 到 0.9999，但 arctanh(0.9999)≈4.95 是个巨值。 别人 z 都在 0.1–0.5，唯独这个假患者是 4.95，一个数就把等权平均拽到 z̄=0.74，tanh 回来 = 0.627。 一个 n=3 的伪满相关患者，几乎单枪匹马定了 HLAthena 的第一名。

# _official_common.py : per_patient_spearman（第 292–298 行）
g = work[work["Patient_ID"] == pat]
n = len(g)                                   # ← 拿的是「患者总行数」= 12
rho = spearman_np(x, y) if n >= min_pep else nan   # 门槛用 12，不是有效点数 3
ns.append(float(n))                          # 传给聚合剔除的 n 也是 12
打个比方：班里 40 人只交了 3 份卷子，碰巧全 100 分。规矩是「至少 5 份才算班级平均分」， 但你数的是「全班 40 人」而不是「实际交卷 3 人」，于是 40>5 通过，虚高满分记进了年级排名。 防线没坏，是数错了分母。

四环里前两环（数据漏 + 数学必然）躲不掉，唯一出错也唯一能修的是第三环：门槛该数「工具实际打了几分（effN）」， 却去数了「患者一共几行（len g）」。

修正：门槛改用有效覆盖 effN

把门槛从 len(g) 改成有效非 NaN 点数 effN，不足的患者剔出聚合。 门槛必须 ≥5 —— effN≥3 修不干净（HLAthena 的 P101 effN 正好 =3 卡线逃过， netMHCstabpan 甚至假分冲到 0.854）：
