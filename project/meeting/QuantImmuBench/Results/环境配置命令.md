  -o /work/out.csv --modelXG neoant --type recombinant

- 输出关键列：`PredIG`（0-1 免疫原性分）

- HPC singularity 非 root 访问 `/root` 被拒 + 无 fakeroot（无 subuid 映射）→ HPC 未真跑，以上为本地 docker 验证。HPC 真跑需 fakeroot 或重打包到非 `/root`。
- WSL 需开 `vsyscall=emulate`（`.wslconfig` 加 `kernelCommandLine=vsyscall=emulate`）→ 容器内老 netMHCpan 二进制不再 segfault。

### ⑤ 正式跑命令（两步流程：feature_calc → Predict）
```bash
# 来源：scripts/improve/run_feature_calc.sh（WSL bash，全量 26790 行；--smoke 取前 20 行）
# 步骤 0：建 ProgramDir symlink（netMHCpan-4.1 / PRIME / MixMHCpred-master）
# 步骤 1：列名 WT_peptide->Norm_peptide
# 步骤 2：feature_calc（improve env，跳 netMHCstabpan → Stability=NaN）
conda run --no-capture-output -n improve python3 "$FEATURE_CALC_PY" \
    --file "$PREPPED_INPUT" --dataset elispot \
    --PredDir "$PRED_DIR" --ProgramDir "$PROG_DIR" --TmpDir "$PROG_DIR" \
    --outfile "$FEATURES_OUT"
# 步骤 3：Predict Simple（improve_new env）
conda run --no-capture-output -n improve_new python3 "$PREDICT_PY" \
    --file "$FEATURES_OUT" --model Simple --outfile "$PREDICT_OUT"
```

### 已知坑（含 PRIME.x 死循环修复，关键）
- **PRIME.x 死循环（2026-06-28 定位真因）**：MixMHCpred wrapper 内部调 `python3`（PATH 解析）。orchestrator 用 `envs/improve/bin/python` 起脚本但没 `conda activate` → 子进程 PATH 无 `improve/bin` → `python3` 解析到 `/usr/bin/python3`（无 numpy）→ MixMHCpred `import numpy` 崩 → 产空 temp 文件 → PRIME.x（`lib/PRIME.cc` 的 `while(!file.eof())`）读空文件 eofbit 永不置位 → 99% CPU 死循环、输出 0 字节、几十分钟不返回。
  - **修法**：把 improve env 的 `bin` 注入子进程 PATH，使 MixMHCpred 的 `python3` 解析到带 numpy 的 improve python3。来源 `scripts/phaseB/run_improve_101102.py`：
    ```python
    improve_bin = os.path.dirname(PY_FEATURE)  # /root/miniconda3/envs/improve/bin
    env["PATH"] = improve_bin + os.pathsep + env.get("PATH", "")
    ```
  - 配套：WORK 目录用原生 WSL ext4（`/tmp/improve_phaseB_work`），避开 `/mnt/d` drvfs 海量小文件 I/O 奇慢。
- netMHCstabpan：HPC el8 仅 glibc 2.28，二进制需 GLIBC_2.29 → HPC 跑不了；仅 feature_calc 的 Stability 特征用它，降级跳过（Stability=NaN，Predict 脚本 `fillna(col.mean())` 自动 impute）。
- 肽长适用 8-12mer。
